# 改进需求清单（v2.0 完整版）

> 本文档为产品方提交的完整需求原文归档，开发按「四、开发顺序」逐模块推进，一次一个模块，做完确认再继续。
> 所有热量 / 营养 / 品牌数据均为**估算值**，标注「仅供个人减脂参考，不构成医疗建议；品牌数据以官方为准」。

---

## 一、核心功能需求

### 1. 热量计算要专业，不只是手工加减

热量计算器必须基于「食物标准热量库」计算，支持：

- 按份计算：如 1 杯奶茶、1 个包子、1 串烧烤；
- 按 100g 计算：如火锅食材、肉类、蔬菜；
- 输入份数或克重，自动换算总热量；
- 自动合计总热量，并显示分类小计，如小吃 300 kcal + 奶茶 400 kcal；
- 同时估算蛋白质、脂肪、碳水；
- 根据总热量给出评估：<300 轻食 / 300–600 适中 / >600 偏高；
- 支持把计算结果保存到今日饮食记录。

补充：单位统一用 kcal（千卡），不要混用「卡路里」。

### 2. 八大菜系独立模块

在导航栏中新增「八大菜系」模块，与「食物库」并列。点击后下拉展示：鲁菜、川菜、粤菜、苏菜、闽菜、浙菜、湘菜、徽菜。

每个菜系展示：

- 所属地区；
- 特色口味；
- 辣度：不辣 / 微辣 / 中辣 / 特辣；
- 甜度；
- 代表菜卡片。

代表菜卡片复用食物库卡片模板，包含：菜名、单份热量、营养要点、减脂提示、辣度、地区、加入计算器、记一笔。

建议补充字段：菜系、代表菜、口味标签、辣度、热量、蛋白质、脂肪、碳水、科普短句。

### 3. 搜索框旁增加相机按钮

点击后：

- 调用手机相机或上传图片；
- 前端预览图片；
- 模拟识别出 1–3 个候选食物；
- 用户选择正确食物；
- 输入份数/克重；
- 加入计算器或直接记一笔。

可接入 AI 图像识别 API。

### 4. 品牌热量库模块

内置常见品牌餐品热量估算数据。品牌范围尽量广，例如：蜜雪冰城、喜茶、瑞幸、库迪、汉堡王、达美乐、醉得意等。

每条数据包含：

- 品牌；
- 品类，如奶茶、咖啡、汉堡、披萨、中式快餐；
- 餐品名；
- 规格，如中杯/大杯/500ml；
- 热量 kcal；
- 蛋白质、脂肪、碳水、糖、钠；
- 数据来源备注；
- 更新日期。

支持品牌筛选、搜索、热量排序、加入计算器、记一笔。

注意：品牌配方会变，必须标注「估算值，以品牌官方小程序/包装为准」。

### 5. 运动消耗模块

运动包括：跑步、散步、快走、慢跑、骑行、跳绳、游泳，以及健身房器械：跑步机、椭圆机、动感单车、划船机、史密斯架、龙门架、腿举机等。

每个动作包含：

- 运动名称；
- 分类：有氧 / 力量 / 拉伸 / 器械；
- MET 值或每分钟消耗估算；
- 动作分解；
- 动作要点；
- 常见错误；
- 温馨提示；
- 安全警告；
- 消耗某份食物需要运动多久。

计算逻辑：用户设置体重后，估算「吃进去的热量需要运动多少分钟才能消耗」。补充：运动消耗和体重有关，建议增加「体重设置」，默认 60kg。

### 6. 手账贴纸图标系统

每个食物、菜系、品牌、运动都有固定图标。优先使用 emoji + CSS 形状 + 统一配色，不依赖外部图片。图标风格统一：圆角、描边、柔和棕橙点缀，让用户一眼记住网站。

### 7. 记录热量时标明克重

每条饮食记录必须保存：

- 食物名称；
- 份量单位：份 / 个 / 杯 / 碗 / 串 / 克；
- 数量；
- 克重，如约 350g；
- 单位热量；
- 总热量；
- 餐次；
- 日期时间。

显示时写成：「1 杯 500ml / 约 350g，总热量 420 kcal」。

### 8. 营养搭配食谱分区

新增「营养食谱」模块，包含：

- 每日营养目标：热量、蛋白质、脂肪、碳水、膳食纤维、水；
- 低卡三餐搭配模板；
- 早/午/晚/加餐推荐；
- 每个食谱显示总热量和营养素；
- 可一键加入饮食记录。

目标：低卡的同时保证蛋白质、膳食纤维、维生素和矿物质摄入。

### 9. 食品科普内容

位置：首页科普卡片 + 食物详情页。示例：

- 西蓝花较同类蔬菜富含蛋白质及矿物质，有一定抗癌相关营养优势；
- 高糖食品可能更容易致痘；
- 反式脂肪、游离糖、GI/GL、烹饪方式对热量的影响。

每条科普标注「仅供个人减脂参考，不构成医疗建议」。

### 10. 营养物质分类模块

按营养素分类找食物：

- 高蛋白；
- 高膳食纤维；
- 低 GI；
- 高钙；
- 高铁；
- 富含维生素 C；
- 富含钾；
- 低脂；
- 低糖。

点击分类后，筛选出含有该营养素的食物卡片。

### 11. 扩充全国饮食数据库（分批交付）

在现有食物库数据结构基础上，新增「全国饮食」数据，要求：

- 覆盖范围：34 个省级行政区，每个省级行政区至少 3 条代表性食物，优先覆盖：北京、天津、河北、山西、内蒙古、辽宁、吉林、黑龙江、上海、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东、广西、海南、重庆、四川、贵州、云南、西藏、陕西、甘肃、青海、宁夏、新疆、香港、澳门、台湾。
- 每条食物字段（必须与现有 FOODS 模型一致）：
  - `id`（唯一，格式 `cn-省份缩写-序号`，如 `cn-sc-001`）
  - `name`、`icon`（emoji）
  - `region`（大区）、`province`（省）、`city`（城市）
  - `cuisine`（菜系 / 类型，如 川菜、粤菜、地方小吃）
  - `spicy`（辣度：不辣 / 微辣 / 中辣 / 特辣）
  - `unitMode`（serving / gram）、`servingName`、`servingGram`
  - `per100`（每 100g 的热量、蛋白质、脂肪、碳水）
  - `nutrition`（营养要点）、`tips`（减脂提示）、`science`（科普短句）
- 分批交付：每批 60 条，按地域大区划分（第一批华北、第二批东北……），不要一次性输出全部。
- 数据准确性：热量按常见做法估算，标注「估算值」，不虚构精确到个位的官方数据。
- 数据文件独立：不要把数据写进 index.html，单独建 `data/foods-cn-华北.js` 这样的文件，用 `<script>` 引入，避免主文件过长。
- 辣度必须真实：按当地常见做法判断，不要所有菜都写「不辣」或都写「特辣」。
- 每条食物必须能和现有卡片模板、计算器、记录页复用，不新增字段结构。

## 二、通用能力与全局体验

- **每日热量目标与进度环**：用户可设置每日目标热量，首页显示已摄入 / 剩余。
- **收藏 / 常吃 / 最近添加**：方便快速找到常吃食物。
- **饮食记录编辑、删除、导出**：记录可改份数、克重、餐次、日期。可导出 JSON 或 CSV。
- **近 7 天热量柱状图**：纯 CSS 或 div 高度实现，不引入图表库。
- **食物详情页统一模板**：食物库、八大菜系、品牌热量都复用同一个详情页。
- **空状态与错误提示**：搜索无结果：「没有找到相关食物，换个关键词试试。」；输入校验：「份数/克重必须大于 0。」
- **数据来源与免责声明**：所有页面底部备注：「热量为估算值，仅供个人减脂参考，不构成医疗建议。品牌数据以官方为准。」
- **单位换算表**：杯、个、碗、串、份、克、毫升。例如：1 杯奶茶约 500ml，1 个包子约 80g。
- **本地存储版本管理**：localStorage 加 key 前缀和版本号，避免以后改字段导致旧数据报错。
- **XSS 防护**：用户输入的餐次、备注等，渲染前要转义。
- **响应式移动端**：卡片在手机上一列，桌面两到三列。
- **搜索历史 / 热门搜索**：可选，提升体验。
- **辣度、口味、菜系统一标签**：辣度统一：不辣 / 微辣 / 中辣 / 特辣。口味统一：清淡、咸鲜、麻辣、甜、酸、香辣等。
- **品牌数据更新日期**：每条品牌数据加「更新日期」，避免用户误以为永久准确。
- **运动安全提示**：器械动作必须写：热身、姿势、呼吸、禁忌、疼痛时停止。

## 四、建议开发顺序

每次只做一个模块，做完确认再继续。建议顺序：

1. 全局设计系统 + 导航 + 数据结构
2. 食物库：卡片、搜索、筛选、排序、详情、收藏
3. 热量计算器：按份/按 100g、小计、评估、保存记录
4. 饮食记录：localStorage、日期分组、餐次、编辑删除、7 天柱状图
5. 八大菜系模块
6. 品牌热量库
7. 运动消耗与动作指导模块
8. 营养食谱 + 营养素分类
9. 食品科普 + 食物详情页
10. 拍照识别模拟版

> 其中，食物库的数据结构最重要，因为八大菜系、品牌热量、营养食谱、计算器、记录页都要复用它。建议先做「全局设计系统 + 食物数据模型 + 食物库卡片」。
